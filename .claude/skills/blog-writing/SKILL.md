# U-Saver 블로그 글쓰기 지침 (2026-11-27 개정)

이 지침은 `ai-docs/plans/blog-keywords/autopublish/prompt.md`와 두 집필 계획의 "글 작성 규칙"을 대체한다.
개정 이유는 `ai-docs/lessons/2026-11-27-scaled-autopublish-deindex.md`, 진행 상황은 `ai-docs/plans/2026-11-27-blog-index-recovery.md`에 있다.

## 1. 발행 원칙

- 자동 발행을 하지 않는다. `autopublish/enabled`는 `off`로 둔다. 글은 사람이 읽고 승인한 뒤 올린다.
- 발행은 주 2편 이하로 한다. 회복 판정일(2027-01-31) 전에는 새 글을 쓰지 않고 남은 22편만 보강한다.
- 주제는 "아이폰 + 외장 저장장치(USB 메모리·SD 리더·외장 SSD·하드)"로 한정한다. 게임기·Android·Windows 전용·카메라·드론처럼 U-Saver 독자가 아닌 주제는 쓰지 않는다.
- 쓰기 전에 `bun ai-docs/plans/blog-keywords/post-ledger.ts check --slug <slug>`로 중복을 검사한다(AGENTS.md 규칙).

## 2. 근거 규칙 — 직접 경험이 글의 중심이다

공식 문서를 다시 요약한 글은 검색 1페이지에 오르지 못한다. 공식 문서가 이미 그 자리에 있다.

- **시험 환경 줄을 둔다.** 본문 첫 `##` 앞에 한 줄로 "시험: iPhone 모델 · iOS 버전 · 저장장치 제품명 · 날짜"를 쓴다. 칸이 직접 시험한 값만 쓴다.
- **직접 해 본 결과를 한 단락 이상 쓴다.** 무엇을 연결했고, 어디서 막혔고, 어떻게 풀었는지 적는다. 실패 사례가 성공 사례보다 값지다.
- **실측값을 하나 이상 넣는다.** 예: 사진 1,000장 복사 시간, 4GB 넘는 영상 복사 결과, 인식까지 걸린 시간.
- **이미지는 3장 이상 넣는다.** 실제 화면 캡처나 연결 사진을 쓰고, 파일은 `public/blog/<slug>/`에 상태 표시줄을 지운 webp로 둔다. 대체 텍스트에 무엇을 보여 주는지 쓴다.
- **시험하지 않은 내용은 단정하지 않는다.** 대신 출처를 붙인다(Apple·Microsoft·제조사 공식 문서 링크).
- **면책 문장을 쓰지 않는다.** "이 글은 ~를 시험하지 않았습니다", "특정 제품을 추천하지 않습니다", "~를 약속하지 않습니다" 같은 문장은 빼고, 대신 시험한 범위를 시험 환경 줄로 밝힌다.
- 근거(시험 환경·실측·사진)가 아직 없는 보강은 구조·문장만 고친 "1차 보강"으로 게시하고, 회복 계획의 해당 항목을 미완료로 둔다. 시험 결과를 지어내지 않는다.

## 3. 구조 규칙 — 틀을 반복하지 않는다

86편이 같은 틀(핵심 요약 → 질문형 H2 10개 → 표 → FAQ)이었고, 기계가 찾기 쉬운 패턴이었다.

- `## 핵심 요약` 헤딩을 쓰지 않는다. 첫 문단 2~3문장에서 검색한 질문에 바로 답한다.
- 질문형 `##`를 3개 이상 연달아 쓰지 않는다. 소제목은 독자가 할 일 순서(확인 → 연결 → 옮기기 → 문제 해결)로 단다.
- `##`는 4~7개로 한다. 글마다 구성이 달라야 한다. 쓰기 전에 가까운 글 2편의 소제목을 보고 같은 순서를 피한다.
- FAQ는 GSC에 실제로 들어온 검색어가 있을 때만 두고, 3문항 이하로 한다. 본문에 이미 답한 질문을 FAQ로 되풀이하지 않는다.
- 표는 비교할 값이 3행 이상일 때만 쓴다. 한 글에 2개까지.
- 내부 링크는 남은 22편 안에서 2~4개만 건다. 링크마다 왜 읽어야 하는지 한 구절을 붙인다.

## 4. U-Saver 사실 규칙

- U-Saver는 NextGenAI가 만든 앱이다. 일반 USB에 사진·영상·연락처를 저장한다. App Store에서 받는다. iOS 26 이상. 4,900원 한 번 결제(en·ja는 "한국 기준" 표기).
- USB는 exFAT 또는 FAT32여야 한다. NTFS는 지원하지 않는다. FAT32는 4GB 넘는 파일을 저장하지 못한다.
- 메시지·앱 데이터·아이폰 설정은 저장하지 않는다. USB 내용은 암호화되지 않는다. 두 고지는 U-Saver 단락에 함께 쓴다.
- "전체 백업", 복원(restore·復元), 화면 잠금 중 백업을 쓰지 않는다.
- SD·microSD·외장 SSD·외장하드의 U-Saver 동작은 실기 검증 전이다. U-Saver 문장에는 USB 메모리만 쓴다.
- U-Saver 단락은 글마다 하나, 본문 끝 쪽에 둔다. 스토어 버튼은 레이아웃(`StoreButton`·`StoreQr`)이 붙이므로 본문에 스토어 URL을 쓰지 않는다.

## 5. 언어별 규칙

- ko를 먼저 완성하고, en·ja는 같은 사실로 그 나라 검색어에 맞춰 다시 쓴다. 문장 단위 번역을 하지 않는다.
- ja는 です・ます체, en은 2인칭 평서문으로 쓴다. 각 언어의 제목·description에 그 언어의 실제 검색어(GSC 쿼리)를 넣는다.
- en 최종본은 `stop-slop` 스킬 기준(상투 전환구·3단 나열·과장 형용사 제거)으로 다듬는다.

## 6. 한국어 최종 윤문 — im-not-ai humanize-korean v2.4.8

ko 본문을 다 쓴 뒤 게시 전에 반드시 돌린다.

1. 버전 확인: `~/.agents/vendor/im-not-ai/update.sh --check` (exit 0 = 최신). 스킬 파일의 `version`이 2.4.8 이상인지 본다.
2. `humanize-korean` 스킬을 로드하고 절차를 따른다. 장르는 `blog`, 경로는 shim의 `route_hint`를 따른다.
3. 입력은 frontmatter를 뺀 본문만 넣는다. 표·링크·수치·제품명·Apple 메뉴 이름은 보존 대상이다.
4. `verify_gates.py` exit 0 또는 1만 채택한다. exit 2면 윤문본을 버리고 스킬 절차대로 재실행한다.
5. 윤문 뒤 링크 수와 표 수가 원문과 같은지 확인하고, frontmatter를 다시 붙인다.
6. 작업 폴더 `_workspace/`는 커밋하지 않는다.

## 7. 작성자와 썸네일

- 작성자는 개발자 포크코딩이다. 이름은 `src/content/site.ts`의 `blogCopy[lang].authorName`(ko "포크코딩", en·ja "Fork Coding"), 링크는 `src/content/seo.ts`의 `authorUrl`(https://www.fork-coding.com)이다. 글 머리 표시·`<meta name="author">`·JSON-LD `Person`이 이 값을 쓴다. 본문에 작성자를 따로 적지 않는다.
- 썸네일은 글마다 하나, `public/blog/<slug>/thumbnail.webp`(1200×675)다. 없으면 빌드가 멈춘다.
- 만들기: `bun scripts/blog-thumbnail.ts <slug> --note "<장면>"`. codex CLI 이미지 생성으로 ko 제목·요약에 맞춘 그림을 만든다. 빠진 글을 한꺼번에 만들 때는 `--missing`.
- 장면은 글의 주제를 보여 주는 실제 사물 한두 개로 정한다. 그림 안에 글자·로고·사람 얼굴이 없어야 하고, 단자 모양이 실제와 맞아야 한다. 만든 뒤 그림을 직접 열어 확인하고, 틀리면 `--note`를 고쳐 다시 만든다.
- 썸네일은 대표 그림일 뿐 직접 경험 근거가 아니다. 본문 사진 3장 규칙(2절)은 그대로다.

## 8. 게시 전 검사

```bash
S=<slug>
rg -c '^## 핵심 요약' src/content/blog/$S/          # 0줄이어야 한다
rg -n '시험하지 않았|추천하지 않습니다|약속하지 않습니다|did not test|テストしていません' src/content/blog/$S/   # 0줄
rg -c '^## ' src/content/blog/$S/                    # 언어마다 4~7
rg -n 'apps.apple.com' src --glob '!src/content/site.ts'   # 0줄
```

- 빌드는 깨끗한 클론에서 확인한다. 작업 트리에는 gitignore된 `ai-docs/**/*.ts`가 있어 로컬 `bun run build`가 타입 검사에서 실패한다.
- 게시 뒤 GSC URL 검사에서 색인 생성을 요청한다(하루 10건 이하).
